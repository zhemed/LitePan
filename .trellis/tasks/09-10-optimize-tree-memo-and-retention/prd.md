# optimize-tree-memo-and-retention

## Goal

实施残留清单里最后两项「按需」优化（用户批准）：**①批次树/行构建记忆化**、**②上传任务工作集保留策略**。发布 `0.0.28`。

## Requirements

### ① 批次树/行记忆化（前端）
1. 行对象（PanelRow）按 `task_id + updated_at` 记忆化：未变化的任务跨 SSE 增量复用，不再重建
2. 批次节点按**批次签名**（该批次任务数 + 最大 updated_at）记忆化：未变化批次不重新分组
3. 缓存上限保护（避免无界增长）；缓存随组件卸载/数据替换失效
4. 可验证：纯逻辑层提供构建计数，可在 Node 下断言"未变化不重建"

### ② 工作集保留策略（后端）
1. 新增设置项（进入设置页 schema）：`upload_success_retention_days`（默认 30，1-3650）、`upload_success_retention_max`（默认 0=不限，0-100000）
2. Manager 后台清扫：仅清理**终态且成功类**记录（success/skipped/canceled）——超期（>days）或超出条数上限（>max，保留最新）的**任务记录**；**绝不**删除未完成任务、本地文件、云端文件
3. 清扫时机：启动后一次 + 每小时一次（受 runCtx 控制，可优雅退出）
4. 清扫后同步内存与广播删除（前端列表即时收敛）
5. 默认值安全：默认不删任何现有记录（30 天 / 不限条数），用户可在设置页调紧

## Constraints

- 不动上传吞吐相关（并发、500ms 门）
- 保留策略只作用于任务记录（DB 行 + 内存），不触发任何本地/云端删除
- 前端改动仅限记忆化，不改交互与视觉
