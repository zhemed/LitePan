# investigate-residual-maintenance

## Goal

全面盘点本次长会话（0.0.14 → 0.0.27 一系列修复/优化/调查）留下的**残留维护项**，产出可执行清单，避免"修完就忘、只做一半"。只读调查，不改任何东西。

## 调查面（7 类）

1. **仓库**：未跟踪/未提交文件、TODO/FIXME 残留、临时脚本与探针文件
2. **容器与镜像**：悬空镜像、历史 tag、构建缓存、容器日志体积、磁盘占用
3. **数据库**：残留任务行（失败/暂停）、WAL/journal、备份文件堆积、表体积
4. **云端（天翼）**：测试残留（bulk-test-2000 目录树、探针文件 p1921/p1987/bulk_1980_probe）、空目录
5. **宿主**：mounts 下测试文件（2G）、/tmp 探针与备份、旧容器残留
6. **Trellis 档案**：归档任务规模、journal 体积、spec 缺口（如 0.0.27 窗口化 API 契约未沉淀）
7. **未完成事项**：优化报告剩余项、已决策不做项、被阻塞项（115 无账号）、失败任务是否需要补传

## Constraints

- 全程只读：不删除、不修改、不重建。
- 每项残留需给出：位置、体积/数量实测、风险、处置建议（保留/清理/转任务）。
- 无法核实的项明确标注。

## Acceptance Criteria

- [x] 七类逐类实测（构建缓存 17.05GB/镜像 39 个/残留容器 1/云端 190 文件/本地 2G/旧备份 229K/任务 7814 行）
- [x] 残留清单表（位置/量/风险/建议）已产出
- [x] 可执行清单 P0-P3（含 docker builder prune 等 16GB 回收命令）
- [x] 质量门 + 门禁 + 归档 + journal + push
