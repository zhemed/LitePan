# PRD：其它驱动会不会踩 115 同类的直链绑定问题（含 Alist）

## Goal

用户真机确认 115 手机下载已修复后提问：**其它类型的挂载（例如 Alist）会不会出现同样的问题？**
本轮只读排查，结论要回答三件事：

1. 这座 LitePan 现在**实际能挂哪些驱动**；
2. 每个现有驱动的 302 直链**是否也绑定请求方**（UA/IP/cookie），会不会复现"手机报 ERR_INVALID_RESPONSE"；
3. 已上线的**两跳握手是否驱动无关**、能否自动覆盖将来新增的驱动（如 Alist），以及仍会失败的边界。

## Background

- 已修复的失效机理（v0.0.50）：**直链由第三方 CDN 下发且签名绑定"取链时的 UA"** → 安卓浏览器把直链交给
  系统下载组件（UA 不同）→ 403 → 手机 `ERR_INVALID_RESPONSE`。修复方式：两跳握手（先空附件、再由组件
  带着自己的 UA 回来取链 302），实现在 `internal/playback/handoff.go`，判定只看
  「GET + 非 Inline + 安卓浏览器 UA + 302 模式」，**与具体驱动无关**。
- 本仓是精简 fork：`ls drivers/` 目前只有 `115_Open`、`189Cloud`、`LocalFs`（+ `template` 骨架）。

## Requirements

### R1 驱动盘点

- 列出本仓实际注册的驱动（读 `drivers/all.go` 与各 `driver.go`），说明哪些**已移除**（如 Alist 是否存在）。

### R2 逐个驱动的直链性质

- 对每个现有驱动读 `ResolveDownload`（或等价实现），判定其 302 直链：
  - 是否指向**第三方 CDN**（有签名/hotlink 保护）；
  - 是否可能绑定请求方（UA / IP / cookie / Referer）；
  - 是否设置了 `ForceProxy`（走服务器中转，天然绕开该问题）。

### R3 覆盖与边界

- 说明两跳握手对这些驱动的覆盖情况；明确**仍会失败**的边界：
  - 直链绑定 **IP**（客户端与服务器不同出口）时，302 方案无法解决；
  - 系统下载组件**不携带登录态**时，第二跳可能 401（115 真机已证明可带 cookie，但其它驱动需单独看）。

### R4 可执行的下一步建议

- 给出"若要新增 Alist/WebDAV 等驱动，需要提前确认/观察什么"的可操作清单。

## Constraints

- **只读**：不改代码、不改配置、不部署；不改归档任务与历史 journal。
- **网络动作**：本轮默认**不访问外部主机**。若要实测天翼云盘的直链绑定面（在飞牛上做与 115 相同的
  UA 对照，会向 189 的下载域名发两次 1 字节请求），**必须先经用户当轮授权**。
- 凭据/现场纪律：不把生产机地址、账号凭据写入任何文件（任务记录里只用"生产机"指代）。

## Acceptance Criteria

- [x] R1 驱动盘点结论（含 Alist 是否存在）
- [x] R2 每个现有驱动的直链性质判定表（第三方 CDN / 绑定面 / 是否 ForceProxy）
- [x] R3 两跳握手的覆盖说明与仍会失败的边界
- [x] R4 新增驱动时的检查清单
- [x] 零越界：`git status` 仅任务目录；未改代码/配置；未访问外部主机（除非另有授权）
- [x] 任务归档 + journal（不推送，除非用户当轮授权）
