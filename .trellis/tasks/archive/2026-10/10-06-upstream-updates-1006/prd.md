# 调查上游 LitePan 更新（2026-10-06）

## Goal

只读调查：比对上游 `Ponphil/LitePan` 自本方上次核对点 `42a3ee9a`（2026-09-20）以来的新提交，
判断**哪些与 slim fork 相关、哪些不适用、哪些已经收敛**，产出 `research.md` 与移植建议清单。

**本轮不改任何代码、配置、部署与数据**（用户原话"你去看一下" = 只读到底）。

  离线磁力/临时空间。

## Requirements

### R1 拉取上游增量（只读）

- 授权范围：仅 `github.com` 的 `Ponphil/LitePan`，只用 `git fetch`（更新远程跟踪 ref `upstream/main`）
  与 `gh api` 只读查询（commits / tags / compare）。
- 记录：新 HEAD sha、提交数、标签变化、是否有 Release、是否重写历史（`ahead/behind`）。

### R2 逐提交分类

对每个新提交给出：sha、标题、改动范围，并归入以下之一：

- **适用**：与本方在线能力相关（驱动、API、服务、上传、播放、鉴权、部署脚本等）
- **不适用**：依赖本方已删模块或仅涉上游独有文件（如 `dashboard_overview.go`、fnos/jellyfin 反代、
  FUSE 读缓存、STRM 等）
- **已收敛**：本方此前已自行实现/删除，无需动作
- **待拍板**：新能力或行为变更，需要用户决定是否移植

### R3 与本方现状交叉核对

每个"适用"项必须给出**本方现状证据**（文件 + 行号/符号）：是否已存在、是否等价、缺口在哪，
避免"上游有就当缺口"的误判。

### R4 产出与边界

- 产出 `research.md`（含 §0 结论摘要、逐提交证据、适用清单、留档项），并给出一句话移植建议。
- 全程**只读**：不改代码/配置/部署/数据，不提交、不推送、不打标签、不发版；
  不访问 `github.com` 之外的任何主机。
