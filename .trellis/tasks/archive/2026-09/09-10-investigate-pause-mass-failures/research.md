# 调查报告：大批量"暂停后"秒级失败风暴（2026-09-10 14:20）

## 结论

**暂停不是元凶。真正的机制是"账号网络冷却 × worker 无冷却感知"**：

1. `driverexec` 账号级熔断：连续 3 次网络类失败 → 30s 冷却（`netFailThreshold=3, netBackoff=30s`）
2. 冷却期间 `Run()` **立即返回**错误"该账号网络异常，约 N 秒后自动重试"——零网络 I/O、零等待
3. 上传 worker 对这类错误**没有等待/重试**（`worker.go`：非取消错误一律 `failTask` 判死）→ 从队列里毫秒级连续取任务、秒级判死
4. 实测风暴速度：**451 个失败/秒**（752 条失败日志/2 秒，含一轮用户重试 ≈2×）——正是"零 I/O 空转"的特征速度

**用户视角的因果错位**：14:20:17 建批 → 14:20:20 账号进入冷却（3 次静默的瞬时网络失败，**无日志痕迹**）→ 14:20:21-22 风暴烧掉 379 个任务 → 用户在同秒暂停（1620 paused）。"暂停导致失败"实为同时序的误读。

| 代码链 | `exec.go:51` 冷却早退；`worker.go:109` failTask 无网络类等待；"context canceled" 不匹配任何网络标记 ✓ |

## 为什么"3 次静默失败"没日志

`recordNetFail` 在两处被调用（`drivers.Get` 失败、`fn` 失败），但触发它的调用若是**无人记录错误**的路径（如目录预解析 warmTargetDirs 的静默失败）就不会留下痕迹；此外 INFO 级日志下也不会有 HTTP 细节。**触发源无法从现有日志归因**（如实说明）。

## 依然存在的风险（修复前）

- 任何 3 连瞬时网络错 → 30s 冷却 → 大批量队列**秒级成百判死**（提示语承诺"自动重试"，实际任务终态 failed，需手动重传）
- 提示语误导：用户以为会自动恢复
- 现在恢复 1620 个暂停任务，若再遇瞬时抖动 → 风暴重演

## 修复建议（三步，可分开做）

1. **worker 识别冷却并等待重试**：冷却错误改为带类型的错误（如 `CodeRateLimited` + `Details{"retry_after_seconds": N}`），worker 检测到后退回队列头部、sleep 剩余秒数再试（兑现"自动重试"承诺），不再判死
2. **`IsNetworkError` 去自指**：中文标记"网络"会让自家冷却消息自匹配（潜在反馈回路），改按类型判定
3. **批次熔断安全网**：连续 N 个任务同因失败 → 自动暂停批次并通知（"批次已自动暂停：账号网络异常"），杜绝成百无效失败
