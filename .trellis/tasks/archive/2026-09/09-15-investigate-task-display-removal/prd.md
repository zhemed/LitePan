# 仪表盘的「运行任务 / 任务总数 / 后台任务」能否彻底移除（调查）

## Goal

回答一个问题：**仪表盘里「运行任务」「任务总数」「后台任务」这三处展示，以及它们背后的全部关联内容（状态、数据源、API、后端概念），能不能彻底删掉？**

产出 `research.md`：逐处定位 → 判定"真数据 / 恒零 / 硬编码残留" → 划清与**活跃**的上传任务、自动化规则的边界 → 分层删除清单 + 风险 + 反例。

**本轮只读**：不改代码/配置/镜像/容器/数据库。是否执行删除由用户看过结论后另开任务。

## Background（初查线索，待核实）

仪表盘（`web/src/components/admin/DashboardManagement.vue`）里已经有强烈信号：

- `const enabledTaskCount = computed(() => 0);` 与 `const totalTaskCount = computed(() => 0);` —— **硬编码恒零**
- 恒零值分别渲染为：控制台状态行里的「运行任务」（`:328-329`）、概况卡片「任务总数」（`:352-353`）、「后台任务」面板标题下的「N 个任务 · M 个运行中」（`:444-445`）与面板空态「暂无后台任务」（`:466`）

而在**同一份前端里**这些是活跃功能，绝不可误伤：

- 上传任务面板 `web/src/components/upload/TaskPanel.vue` + `FileBrowser.vue` 的 `openTaskPanel`（`upload_tasks` 表、`internal/upload`）——**前端文件页的真实功能**
- 首页页脚的任务入口 `useHomeFooterStatus().openTaskPanel`（同样是上传任务）
- 任务管理页 = 自动联动（`AutomationPanel`，`internal/automation`，**活跃**）

## Requirements

### Q1 逐处定位三处展示

必须给出**文件:行号**与渲染条件：

| 展示 | 位置 | 待判定 |
|---|---|---|
| 「运行任务」 | 控制台状态行 | 值来自什么？是否恒零？还会影响别的 UI 吗（如状态灯/文案分支）？ |
| 「任务总数」 | 概况卡片 | 同上；卡片本身是否还有别的用途？ |
| 「后台任务」面板 | 右列面板 | 面板里渲染的是哪个列表/字段？数据源是真实的还是恒空数组？空态文案是什么？ |

### Q2 判定数据源性质（核心）

对每一处，逐条回答：

- 值是否**恒为零/恒为空**（硬编码、未接线的 ref、永远 rejected 的请求）？
- 有没有**对应的后端 API/服务**在提供它？（逐个端点核实：是否注册、是否被前端调用、返回什么）
- 该字段/请求是否是**其它 UI 分支的输入**（删了会不会连带坏掉别处）？
- 是否存在**只服务这三处**的前端状态/composable/store/api 文件或导出？

### Q3 划清与活跃功能的边界（反例清单）

必须逐项验证并写明**为什么不能删**：

- 上传任务子系统：`web/src/components/upload/TaskPanel.vue`、`web/src/composables/upload/*`、`web/src/api/upload.ts`、`internal/upload/**`、`upload_tasks` 表、`/api/admin/upload*` 与 SSE 端点
- 自动化：`internal/automation/**`、`AutomationPanel.vue`、`web/src/api/automation.ts`、任务管理页签
- 首页页脚的任务入口与 `useHomeFooterStatus`
- `web/src/components/admin/DashboardManagement.vue` 里**同文件**的其它卡片/面板（缓存空间、未读通知、存储账号、日志与通知、控制台"待确认错误"等）

### Q4 运行期证据

- 实例上 `upload_tasks`、`automation_rules`、`automation_runs` 的行数（当前应为 0）
- 仪表盘相关 API（若存在）的真实响应
- 浏览器实测：这三处展示在真实例上渲染成什么（含截图），以及"后台任务"面板在有无数据时的差异（能否在**不污染实例**的前提下造数据验证？若无安全方式则说明）
- 删除后会影响到的**用户可见面**：仪表盘卡片数、状态行、右列面板

### Q5 结论

- 明确回答"能否彻底移除"，并**分三类**给结论：① 前端展示层（卡片/状态项/面板）② 前端状态与 API 封装（若有专属文件）③ 后端（端点/字段/表——预计无，但必须核实）
- 给出**分层删除清单**（含顺序、验证点、回滚点），供后续任务直接引用
- 风险：是否有"删了以后后台仍可能有真实任务却不再展示"的信息缺失（例如上传任务、自动化运行）；若有，必须写明并给出建议
- 若结论为"可以删"，额外评估**仪表盘布局影响**（卡片从 3 张变 2 张？右列面板是否留下空位）
