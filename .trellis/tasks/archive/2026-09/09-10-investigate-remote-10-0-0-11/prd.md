# investigate-remote-10-0-0-11

## Goal

按用户指示排查 **10.0.0.11** 上的 LitePan 实例（该机 SSH root 与实例 admin 使用同一口令）。只读排查为主，产出结论与建议。

## Requirements

1. **连接性与主机基线**：SSH 可达性、主机名/发行版/内核/uptime/负载/磁盘
2. **实例状态**：容器（镜像 tag、启动时间、重启策略、端口映射、挂载、特权）、暴露面（监听地址、防火墙）
3. **应用健康**：`/api/health`、管理登录、账号列表、任务汇总（成功/失败/暂停）
4. **失败归因**：应用日志（`data/log/*` 或 docker logs）中的「上传文件失败/上传暂缓」分类统计；数据库失败任务明细
5. **安全态势**（承前次事故背景）：异常登录（auth log 里的失败/成功来源 IP）、可疑进程、cron/定时任务、SSH 配置（root 登录/密码认证）、与 10.0.0.91 的差异
6. 产出：现状摘要 + 与本地实例（0.0.31）的版本/配置差异 + 风险与建议

## Constraints

- **只读**：不修改 10.0.0.11 上任何配置/服务/数据；如需变更，先出方案并请求授权
- 口令只用于本次连接，**不写入任何被跟踪文件**（不落库、不入库到 git）
- 无法验证的事项明确标注

## Acceptance Criteria

- [x] 连接性与主机基线：fnOS/Debian12/32G/uptime 11h
- [x] 实例 v0.0.31、privileged+pid host、5211 监听 *:5211、UPnP 服务在跑
- [x] health/登录/汇总(72:71成功1失败) + 失败根因定位（WAL 上传途中增长导致 ContentLength 不符）
- [x] 安全态势：0 失败登录、仅本机来源、cron 正常、无异常进程；PermitRootLogin yes 待加固
- [x] 结论与建议清单（产品侧变动文件防御 / 运维加固 / 凭据暴露提示）
- [x] 门禁 + 归档 + journal + push
