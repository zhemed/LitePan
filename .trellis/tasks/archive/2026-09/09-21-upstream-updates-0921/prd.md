# 调查上游 LitePan 最新更新是否有本方需要的改动

## Goal

回答一个问题：**上游 `Ponphil/LitePan` 自上次核查（2026-09-12，`main = 46a0a89`）以来又更新了什么，其中哪些是本精简分支真正需要的？**

产出 `research.md`：上游新提交全量清单 → 逐条适用性判定（值得移植 / 不适用 / 需进一步核实）→ 推荐移植清单（含理由、影响面、风险）→ 明确排除项。

**本轮只读**：不改代码、不改配置、不 merge、不 cherry-pick。唯一允许的副作用是 `git fetch` 更新远程跟踪 ref（不改工作区）。

## Background

- 上游：`Ponphil/LitePan`（GitHub）。本方是它的**私有精简分支**（`zhemed/LitePan`）：仅 3 驱动（115_Open / 189Cloud / LocalFs），已删 STRM、媒体整理、缓存整理、内置离线下载、夸克TV、crosstransfer、share/dav、FUSE、API 秘钥等功能。
- **上次核查（2026-09-12）**：上游 `main = 46a0a89`、tag `v0.5.5-beta`、官方 changelog 已发 `v0.5.5`；当时结论是"47 个提交里 11 个文件级适用、按项评估后多数不适用"（详见 `.trellis/tasks/archive/2026-09/09-12-investigate-upstream-updates/research.md`）。
- **⚠️ 上游曾重写历史**：双方**无共同祖先**（`git merge-base --all` 为空），upstream 当前 lineage 的根 `6313ef7` 与本方根 `a69bb6e` tree 相同、SHA 不同；fork 点为 upstream `f71a522` ≡ 本方 `4c160d9`。**因此不能用常规 merge/rebase 判断"落后多少提交"**，必须用「提交 + 文件路径 + 内容」三要素比对。
- 本方当前基线：`main = 8af1892`、版本 `v0.0.47`（已发布并部署到本机 `:5211`）。

## Requirements

### Q1 上游现状（精确到 sha 与时间）

- 上游 `main` 当前 HEAD（sha + 提交时间 + 标题）、最新 tag、最新 release（含 changelog 文本）
- 与上次核查基准 `46a0a89` 的关系：`46a0a89` 是否仍在上游历史中（若被重写需说明）
- 新增提交总数，以及**时间窗口**（上次核查日 → 现在）

### Q2 新增提交逐条盘点

- 列出 `46a0a89..上游HEAD` 的**全部**提交（sha / 日期 / 标题 / 改动文件数）
- 对每条给出**适用性初判**：改动的文件路径是否存在于本方 tree（剔除上游构建产物 `internal/api/web/**`）
- 标注是否触及本方**已删功能**（上述清单）或本方**自有改动**（冷却等待、熔断分级、上传批次化、日志可观测、版本单一来源、非特权部署等）

### Q3 值得移植的候选（核心）

对每个候选必须给出：

- **上游证据**：commit sha + 文件路径 + 关键 diff 摘要（要能看出改的是什么行为）
- **本方现状**：对应代码在本方是什么样（文件:行号），是否已有等价实现
- **为什么需要**：是缺陷修复 / 行为改进 / 新能力？（**缺陷修复优先级最高**）
- **移植成本与风险**：文件数、是否跨层、是否需要迁移、是否与已有实现冲突
- **建议分级**：`P0 立即移植` / `P1 值得移植` / `P2 可暂缓` / `不适用` / `需进一步核实`

### Q4 明确排除项

- 逐条列出"看起来是更新、但本方不需要"的提交及其理由（例如：属已删功能的改进、纯上游构建产物、依赖不存在的模块、与本方架构冲突）
- 若上游对某文件的重构与本方**已有改动冲突**，必须写明冲突点与处置建议（不擅自合并）

### Q5 版本与发布面

- 上游是否发了新 release / changelog 条目？其宣称的修复是否已在 Q3 覆盖（**交叉印证**：官方条目 ↔ 实际提交）
- 本方是否需要因上游更新而调整版本号/发布计划（仅给建议，不动手）

## Constraints

- **网络范围（严格遵守全局安全红线）**：**只允许**访问上游仓库 `github.com/Ponphil/LitePan`（`git fetch` 与 `gh api` 只读查询）。**不得**访问任何其它主机、API、DNS、内网地址；不得探测端口；不得读取工作区以外的私有配置。用户本轮请求即为该上游仓库的访问授权，超出范围一律先问。
- **只读**：不 merge、不 cherry-pick、不改工作区文件（`git fetch` 仅更新远程跟踪 ref）。所有分析用 `git show`/`git diff` 在临时 ref 上完成。
- 「不适用」的判定必须给**可复核命令**，不允许"看起来不需要"这种结论。
- 不能只凭 commit 标题下结论：**必须看 diff**（标题与实现不符是上游常见情况）。
- 不改 `.trellis/spec/`（若发现规范过时只登记）。
- 本任务**不做**：实际移植（另开任务）、发版、上游同步 merge。
