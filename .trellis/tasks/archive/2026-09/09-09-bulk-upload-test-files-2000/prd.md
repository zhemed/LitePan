# 09-09-bulk-upload-test-files-2000

## Goal

生成 **2000 个 × 1MB** 独立随机内容测试文件，用于大批量上传吞吐复测（承接 0.0.19 吞吐修复的验证）。落位方案 A 目录 `/root/LitePan/mounts/LitePan-123/`（容器内 `/app/mounts/LitePan-123/`，服务器上传面板可直接选）。

## Requirements

1. 内容必须**互不相同**（每文件独立随机），避免 189 秒传（rapid upload by hash）把测试变成秒传演练。
2. 目录：`/root/LitePan/mounts/LitePan-123/bulk-test-2000/`，文件名 `bulk_NNNN.bin`（0000-1999），单文件 1048576 字节。
3. 磁盘余量充足（实测 215G 可用，占用 2GB）。
4. 校验：文件数 = 2000，单文件 = 1MiB，抽验内容互异（MD5 去重计数 = 2000）。
5. 记录测试路径（容器视角 `/app/mounts/LitePan-123/bulk-test-2000`）与预期吞吐基准（并发=1 + 500ms 门：约 2-4s/文件 → 全批 1-2 小时量级），供复测对照。

## Constraints

- 不自动发起上传（由用户在 UI 服务器上传面板手动执行）。
- 生成用单次 urandom 流 split，避免 2000 次子进程开销。

## Acceptance Criteria

- [x] 2000 个文件就位：`bulk_0000.bin` ~ `bulk_1999.bin`，各 1048576 字节，共 2.0G
- [x] 全量 MD5 校验：2000/2000 唯一（无秒传风险），生成耗时 2.7s
- [x] 测试路径（容器视角）：`/app/mounts/LitePan-123/bulk-test-2000`
- [ ] 用户 UI 复测 + 吞吐基准对照
- [ ] 归档 + push

## 吞吐基准（对照用，0.0.19）

并发=1（用户设置，不动）+ 500ms 账号间隔门。单文件成本 ≈ init(0.5s 门) + 分片 PUT（数据面不过门，1MB 秒级）+ commit(0.5s 门) + 目录解析（本批单目录，预解析吸收）。预估 **~1.5-2.5s/文件 → 全批 50-80 分钟**。复测时看：上传面板 2000 条批次任务、吞吐是否稳定、有无停滞段。
